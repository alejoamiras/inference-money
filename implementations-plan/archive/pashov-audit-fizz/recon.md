## L1 facts that shape the design

- **Portal today**: direct deposits name `msg.sender` (`TokenPortal.sol:127-158`); `...For` deposits are router-only and name the router's `_depositor` (:136-168, `_requireRouter` :259). Pulls always from `msg.sender` (`_pullExact` :273-277). Virtual guards :252-270.
- **Router today**: Permit2 owner = `msg.sender`, so "only the signer may submit"; the witness binds recipient, secretHash, privacy (:18-22, :79-90). Permit2 verifies an owner *with code* through ERC-1271 — the SepoliaFork comment (:41-42) records that 7702-delegated famous keys already flip Permit2 into `isValidSignature`.
- **Gas gate**: `.gas-snapshot` holds `test_gas_depositPrivate` 590426 and `test_gas_depositPublic` 592836; `test:evm:gas` checks at 2 %. No gas test covers a direct portal deposit.
- **`forge test` compiles everything under `test/`**, fizz included: a fizz call site that no longer type-checks fails `test:evm`.
- **`ITokenPortal`** declares only the two `...For` functions; changing them moves the router, `MockTokenPortal` (`C/test/mocks/MockPortal.sol:30-47`) and the fizz `...For` helpers together.
- **Call sites that change** (direct deposits): `TokenPortal.t.sol` (~20 calls; `test_depositPublic_namesTheCaller` :73, `test_depositPrivate_namesTheCaller` :89), `PortalRoundtripFuzz.t.sol:61-82`, `TokenPortalInvariant.t.sol:105-150` (`fail_on_revert = true`), `FormalPortal.t.sol:140-198,302-321`, fizz handlers (`TokenPortalHandler.sol`, `RoundTripHandler.sol:202-210`, `AztecL2Handler.sol:152,165`, `FoundryTester.sol`).
- **Router proof split**: `proveNamesCaller` (`FormalRouter.t.sol:139`) asserts the depositor is the caller for both legs; with an explicit public refund address on the *portal*, the router's public leg is unchanged (it passes the signer), so the proof can stay.

## Aztec facts that shape the design

- **Packed layout** (`DelayedPublicMutableValues<bool, _>`, 3 fields): field 0 holds both timestamps of change and the delay change's `pre`/`post`; fields 1-2 are the value's `pre`/`post`. `get_effective_minimum_delay_at(anchor)` is `post − 1` once the delay change has applied, else `min(pre, (tsc − anchor) + post) − 1`; `get_time_horizon(anchor, d)` is `anchor + d` once the value change applied, else `min(anchor + d, tsc − 1)`. The archived harden lesson (`archive/harden-security-whole-repo/lessons/phase-3.md`) already settled the `delay − 1` reading.
- **Hint today**: `merchant_side_hint` (`hints.nr:36-60`) picks by the `pending` flag alone; `payment_side_hint` (:65-92) uses `probe` only for `.merchant`, so the horizon change does not touch it. `is_merchant_at_anchor` (:113-115) backs `try_prove_merchant` and so the bridge's private exit.
- **Build rules**: any `main.nr`/`hints.nr` change moves the Token class id — commit the `compile.sh` rebuild, then `compile.sh --check` (it diffs HEAD), and update the pin at `B/artifacts.test.ts:15`. Rebuild `token_bridge` too and check whether its class id moved (unverified). Tests under `N/token/src/test/` compile with the contract. No new external function, storage or event, so `abi-superset.test.ts` lists stay; no new `merchant_stamp` constant, so keystone stays.
- **`check-sole-consumer.sh`** reads only `token_bridge/src/main.nr` (+ `claim_secret`, `portal_messages`); the Token-side changes trigger none of its rules. `try_prove_merchant`'s name and signature are pinned there.
- **Demo**: `demo setup` lists merchants before deposits (`demo.ts` `prepare`), seeds alice/bob private claims and a public galactica float; on testnet it refuses unlisted merchants and asks for a keyed `merchants add`. `docs/operations.md:51` orders `merchants add` before `demo setup`, so bind-before-listing reorders the runbook.
