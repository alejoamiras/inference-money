## Presto facts that shape the design

- **SDK** `@alejoamiras/presto@6.0.0-rc.1` (npm `testnet` tag, 2026-09-29, SLSA provenance): ESM only; `PrestoProver extends BBLazyPrivateKernelProver` from `@aztec-labs/bb-prover/client/lazy` (the PXE's own subpath, so no server-only code); without a `simulator` option it dynamic-imports `@aztec-labs/simulator/client`, which it does not declare (`dist/lib/presto-prover.js:2,19,90`); the isolated linker cannot resolve that, so the app passes one. Exact pins: `@aztec-labs/{stdlib,bb-prover,foundation}` and `@aztec-foundation/noir-{acvm_js,noirc_abi}` at `6.0.0-rc.1`, `@alejoamiras/presto-core@1.2.1` (2026-09-29, provenance); `@logtape/logtape@^2.3.2` and `ms@^2.1.3` are ranges.
- **Browser policy**: HTTPS only by default (`https://127.0.0.1:59834`); after an HTTPS failure, one witness-free `GET http://127.0.0.1:59833/health` diagnostic, never HTTP `/prove`. Never probe on load unless `loopbackPermission()` reads `granted` (Chrome 142+ / Firefox 153+ prompt on the first loopback request). `onPhase` reports `transmit` only on the native path and `fallback` when it proves in WASM.
- **Banners** `@alejoamiras/presto-banners@1.2.0` (2026-09-25, provenance): zero dependencies; styles are a `<style>` inside Shadow DOM (needs `style-src 'unsafe-inline'`, already allowed); `fonts="google"` injects a Google Fonts link (blocked by `font-src 'self'`), `fonts="none"` injects nothing; one status-driven surface per page; Billboard paints only `connect` and `offline`, the Ribbon every state; `available` plays a 2 s "Presto connected ✦" morph and hides.
- **presto-server 1.1.3** (release `presto-v1.1.3`, `presto-server-1.1.3-linux-x86_64.tar.gz`, 4.27 MB, one binary, sha256 `90b76733c36ef337f19a326a3263ae0128b83d36bbea9ffb39bb09a4c0c07c41`, verified locally): HTTP only on `127.0.0.1`; `--port`/`PRESTO_PORT` refused unless `PRESTO_HOME` is set; origins: localhost auto-approved, `ALLOWED_ORIGINS=a,b` pre-approves, `--allow-all` disables gating; CORS `*`, `Cross-Origin-Resource-Policy: cross-origin`; downloads `bb` for the requested `x-aztec-version` from `AztecProtocol/barretenberg` releases (a `v6.0.0-rc.1` release exists), checked against GitHub-API digests; cache under `$PRESTO_HOME/versions/`. **It ignores unknown flags and starts serving**: `presto-server --help` bound the default port here, so the harness always passes `PRESTO_HOME` + a claimed port and owns the process group.
- **Presto's own e2e**: HTTPS against the desktop app seeds NSS trust out of band; against headless presto-server it clicks the SDK's HTTP-consent UI; Local Network Access is tested with `--ip-address-space-overrides=<origin>=public` and `context.grantPermissions(["local-network-access"], { origin })` (Playwright ≥ 1.58; this repo pins 1.63.0).
- **This host** already has an owner's `~/.presto` (2026-09-08): a run must never use it.

## Collision and dedup risks

1. Presto's fixed ports vs per-run isolation: solved by claiming ports and passing `PRESTO_HOME` + `PRESTO_PORT` to presto-server, and the same ports to the bundle (local builds only).
2. `minimumReleaseAgeExcludes` takes exact names; a transitive left out stays skipped (`implementations-plan/lessons.md`, archived `usdc-bridge` phase 11): exclude `@alejoamiras/presto` and `@alejoamiras/presto-core`; `presto-banners@1.2.0` ages past seven days on 2026-10-02 21:40 UTC.
3. The CSP strings are asserted verbatim in `target.test.ts`; Presto's origins join only real-proof builds, so fake-proof builds (the main e2e suite) keep their exact CSP.
4. The e2e egress fixture fails any unlisted origin: the Presto spec lists its proxy and server origins (and the CRS hosts, for the browser fallback).
5. `@aztec-labs/simulator` becomes a direct dependency of the showcase (already in the lockfile through the PXE), pinned to `6.0.0-rc.1`.
