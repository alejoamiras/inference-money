## Flags: what our planned router/portal design would currently FAIL

1. **Portal-level `AmountExceedsL2Max` / `InexactTransfer` — genuinely absent from V1's `NuloTokenPortal`.** Read `NuloTokenPortal.sol` in full: it is byte-identical to canonical Aztec `TokenPortal` except the F-001 init guards — `depositToAztecPublic`/`depositToAztecPrivate`/`withdraw` use plain `SafeERC20.safeTransferFrom`/`safeTransfer` with **no amount cap and no balance-delta check**. `TokenPortalImpl.sol` (V2) adds both, proven by `test_clone_rejectsAmountAboveU128` and `test_clone_rejectsFeeOnTransfer`/`test_clone_withdraw_rejectsOverDebit`. **If either V2 test is ported verbatim against the plan's "V1 `NuloTokenPortal` copied verbatim" design, it FAILS** — the portal is a standalone, permissionlessly-callable contract (anyone can call `depositToAztecPublic` directly, bypassing the router entirely), so the router's own `0 < amount <= uint128.max` check does **not** protect a direct caller. A direct deposit above `2^128` would silently corrupt/strand on the L2 side (the Noir bridge's amount type is u128). This is the one place I'd push back on the plan's "byte-identical to canonical" framing: **recommend adding these two guards to the portal itself** — they sit entirely outside the sha256 content-hash preimage (verified by reading the V2 source: `_requireDeposit`/`_pullExact` run *before* the hash computation and *around* the transfer, never touching the hashed bytes), so this does **not** create content-hash drift risk, and it closes a real gap the "byte-identical" framing currently leaves open. This is a decision for the user/plan owner, not something to silently do — flagging it explicitly as requested.
2. **Portal has no `nonReentrant`.** Neither canonical `TokenPortal` nor V1's fork has one; V2's `TokenPortalImpl` added `ReentrancyGuardTransient`. Low real risk since USDC has no transfer hooks (unlike the `HookERC20`/`ReenteringERC20` mocks V2's tests use), but a V2-style `test_clone_*ReentersDeposit/Withdraw_rejected` test **would FAIL if ported verbatim** against an unguarded portal (it would need a hooking mock token to even trigger, and then the call would simply succeed the second time rather than reverting). Recommend either (a) add the guard for defense-in-depth given "top quality" is the bar, or (b) explicitly skip this test class with a comment explaining USDC has no hooks so the property is vacuous for the deployed token — don't port it silently as if it passes.
3. **Any test asserting `SwapBridgeRouter.ForeignPortal`/`FuelOnlyLeg`/`setSwapTarget`/`sweep` won't even compile** against the new `Permit2DepositRouter` (those symbols don't exist in the new design) — these must be **deleted**, not "adapted with a TODO," when porting test files wholesale. Listed explicitly above per-file so nothing gets copy-pasted and left half-broken.
4. **V2's `.gas-snapshot` values are not reusable numbers** (different contract, no fuel/swap overhead) — a fresh baseline must be captured, not diffed against V2's `655910`/`240769`.
