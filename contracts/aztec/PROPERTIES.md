# Properties

> Generated by the fizz invariant-discovery lenses (conservation, state transitions, round trips and boundaries,
> adversarial, protocol spec), adapted to Aztec.nr, then merged by the fizz synthesizer. Nothing in this file is
> implemented by this run: it lists properties of the Aztec contracts and maps each one against the existing TXE tests.
>
> Each entry has one of three states:
> - `[x]` an existing TXE test already asserts it (cited on its Coverage line);
> - `[~]` a test exercises it without asserting all of it (the gap is named);
> - `[ ]` no TXE test asserts it. A `TXE-UNREACHABLE` entry needs something TXE does not have (a kernel, a PXE, L1,
>   public logs, enqueued-call inspection, a batched tx, tx phases); its Coverage line names the layer that could check
>   it and whether that layer already does.
>
> IDs are stable. Do not renumber. Add your own entries under any unused `GL-NN` / `SP-NN`.
>
> **Guarantee.** `SHOULD-HOLD` is backed by the cited evidence: docs/*.md, AGENTS.md, the archived
> galactica-compliant-usdc plan's accepted design, a documented aztec-nr library contract, or an exact identity in the
> code. A violation is a confirmed bug. `EXPLORATORY` is inferred; a violation is a lead for review.
> **EXPECTED-FAIL today** marks a property the current code would fail (see "Known audit findings").
> **SYN** marks a property the synthesizer added for an open audit finding no lens targeted.
>
> **Roles.** A user is any account not on the token's merchant list. A merchant is listed and switched on at the block
> that matters. A switched-off merchant is a user once its switch-off lands.
>
> **Paths** are relative to `contracts/aztec/` unless they start with `packages/` or `docs/` (repo root). Sources name
> the discovery lenses' raw ids: CON (conservation), ST (state transitions), RT (round trips and boundaries), ADV
> (adversarial), SPEC (protocol spec).
>
> **What TXE can and cannot see (aztec-nr v6.0.0-rc.1).** `get_last_tx_effects()` returns note hashes, nullifiers and
> private logs; there is no public-log reader, no L2→L1 message reader and no view of enqueued public calls. A
> `should_fail` test ends at the failure, so state after a refused call is unobservable. TXE runs no kernel or PXE
> (existence requests and expiry are not enforced, nothing is rounded) and cannot put two calls in one tx.
> `env.private_context_at(token, |ctx| …)` followed by `ctx.finish().expiration_timestamp` does read an in-circuit expiry
> cap. `with_public_initializer` deploys with deployer zero (universal); `txe_oracles::deploy` takes a deployer.

   the probe compares each entry's horizon. **SP-30** covers it; SP-34 pins the caps the pick compares; GL-31 is the

4. **A stamped request stays payable after its merchant's switch-off, for any amount and with no end date** (accepted
   by the owner). **GL-12** pins the accepted behaviour (SHOULD-HOLD, passes); **GL-13** is its converse (EXPLORATORY,
   EXPECTED-FAIL today), to implement only if the residual is revisited. GL-02 bounds the residual: every payment into
   such a request is debited from its payer and lands only with the request's owner.
5. **A private completion of amount 0 was accepted, and the recipient's PXE discovers only the first completion.**
   Fixed: `transfer_private_to_commitment` refuses a zero amount; **SP-07** covers it. GL-02 holds the "first
   completion only" half (accepted, upstream; its discovery half is unreliable in TXE), and SP-17 limits who can do it
   to the designated completer.

Other properties the current code would fail, outside that list: **SP-28** (a capsule naming the creator pads a
merchant-to-merchant request, against docs/architecture.md), **GL-05** (a public payment to the zero address breaks
the `Transfer`-event books). **GL-34** (TokenPortal accepted a zero deposit no L2 call can consume) is fixed on L1: every
deposit path refuses zero.

Documentation that disagrees with the code: docs/architecture.md "Expiry" (a pending change on a 24 h entry can leave

burns" (holders can burn directly; GL-43); upstream's note in token/src/test/mint_to_commitment.nr that "the protocol still
prevents" double completion (GL-02).
