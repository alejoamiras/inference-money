## Synthesis notes (for implementers)

- Dedup merges: CON-01=SPEC-B01; CON-02=ADV-01=SPEC-B02(>=); CON-03=SPEC-B02(==)=ADV-15; CON-08/09 = VS-07/VS-05 = ADV-04 = SPEC-B09 (split into GL-08 balance and GL-09 allowance); CON-12=VS-02=ADV-13=SPEC-B03a; CON-16=VT-03=VS-01=SPEC-B06; ADV-08=SPEC-B07a; ADV-10 state half=VS-06=SPEC-B14; RT-09 kept standalone (different assertion from GL-01..04); VT-01=ADV-17; ST-02=RT-06; ADV-14b=SPEC-B10; RT-07=SPEC-B16; RT-08=ADV-06=SPEC-B11; RD-02=ADV-16; CON-10 split between SP-01 and SP-02.
- Non-mergeable: no V-06 exists (not a vault). C2 (repeated cycle dust extraction) = RT-04 = SP-19, kept standalone with its own round-trip handler. No source was tagged [MANDATORY].
- Correction to ADV-18 (GL-30): `ModalUsdc` fee is `value * 100 / 10_000`, which floors to 0 below 100 units, so flag acceptance only when `amount >= 100` (FeeOnTransfer deposit, SenderSurcharge withdraw). A SenderSurcharge direct deposit and a FeeOnTransfer withdraw are legitimately exact and must not be flagged.
- Dropped helper ghosts (replaced by direct assertions or snapshot fields): `reserveShrank` (SP-09 uses snapshots), `misroutedMessages` (SP-04 / GL-11 assert directly), `initDeniedToInitializer` (SP-14 asserts inline), `lastInboxIndex` (SP-05 compares the returned index with `inbox.sent() - 1`), `exitStateHistory` (forward-only exit state is implied by GL-07 + GL-15 + SP-06), `stuckExits`/`livenessBroken` (replaced by `payableExitStuck` and `depositLivenessBroken`).
- Violation-counter properties (GL-17..24, 28..31) are cheap `eq(ghosts.x, 0)` gates; the detection logic lives in the handlers named in the wiring plan. Inline `SP-*` assertions run in the handler (Medusa/Echidna assertion mode, `failOnAssertion: true`).
- Global loop properties (GL-06, 07, 12, 15) iterate `exitMsgs`/`depositMsgs`, bounded by the <=100-call sequence length. GL-15 wraps the Outbox view in try/catch and skips the entry on revert. No GL calls anything else that can revert.
- Global properties that read `ghosts.withdrawn`-derived identities (GL-06, 07) are gated on `unbackedPayouts == 0` so one root-cause violation does not fire every identity.
- Notes on handler behaviour: unclamped deposit handlers revert in FeeOnTransfer/SenderSurcharge/blacklist modes (the portal's exact checks); the post-call SPs run only on success. When `tokenPortal_withdraw_clamped` is converted to try/catch, wrap `portal.withdraw` inline (not `this.tokenPortal_withdraw`) so `vm.prank` state is not left dangling by a revert.
